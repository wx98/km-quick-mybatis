# 缓存关系侧边栏实施方案

## 1. 目标与边界

新增一个项目级 IntelliJ Tool Window，展示当前项目持有的 MyBatis Java/XML 缓存，并以 SQL ID 为中心展示 Java 与 XML 的关联关系。

本阶段只确定实现方案，不修改业务代码。实现时必须使用 IDEA MCP 做代码搜索、局部补丁和编译验证；不得重新生成已有的整文件。

默认行为：

- Tool Window 停靠右侧。
- 使用 IntelliJ 内置项目图标。
- 默认打开“当前”页签。
- 默认显示“全部缓存”。
- 默认“所有”数据类型。
- 默认不分组。
- 搜索框默认关闭。

## 2. 现有代码复用点

IDEA MCP 已确认当前工程存在以下入口：

- MyBatisCache 接口：提供 SQL ID 到 Java/XML 元素的双向查询。
- MyBatisCacheDefault：提供实际缓存快照和文件级查询。
- JavaElementInfo：保存 Java 文件路径、元素类型、SQL ID、起止偏移量。
- XmlElementInfo：保存 XML 文件路径、标签名、SQL ID、databaseId、起止偏移量。
- MyBatisCacheManagerDefault：负责项目级缓存、刷新、文件变化监听和缓存版本。
- TagLocator：根据文件路径和偏移量定位 Java PSI 或 XML 标签。
- RefreshActionGroup：已有右键刷新菜单，包含全部、XML、Java、Java 方法调用刷新。
- Icons：已有插件图标常量，但没有 Tool Window 专用图标。

实现原则：

1. Tool Window 只通过缓存服务读取数据，不直接访问 DAO 或数据库。
2. 刷新动作复用现有 RefreshActionGroup，不复制刷新逻辑。
3. 所有树节点只保存文件路径、偏移量和业务值，不缓存 PSI 对象。
4. 后台线程构建快照，EDT 更新树模型。
5. 缓存版本发生变化时，旧查询结果必须丢弃。

## 3. Tool Window 设计

在 plugin.xml 增加 Tool Window 扩展：

- id：Km Quick Mybatis
- anchor：right
- factoryClass：MyBatisCacheToolWindowFactory
- icon：AllIcons.Nodes.Project

如果 XML 扩展无法直接解析内置图标字段，则由 Factory 创建内容后调用 toolWindow.setIcon(AllIcons.Nodes.Project)。

建议新增包：

- toolwindow
- toolwindow.action
- toolwindow.model
- toolwindow.query
- toolwindow.navigation
- toolwindow.settings

建议新增类：

- MyBatisCacheToolWindowFactory
- MyBatisCacheToolWindowPanel
- CacheRelationQueryService
- CacheRelationSnapshot
- CacheTreeNode
- CacheTreeNodeKey
- CacheNavigationService
- CacheToolWindowState

不要修改现有缓存类的职责，除非为了增加只读查询方法或缓存变化通知。

## 4. 顶部工具栏

工具栏从左到右：

1. 刷新。
2. 搜索。
3. 视图选项。
4. 全部缓存/仅关联关系。
5. 弹性空白。
6. 全部展开。
7. 全部收起。

所有按钮使用 IntelliJ AnAction、ActionToolbar 和标准图标，并提供 Tooltip。

### 4.1 刷新

点击刷新按钮弹出已有 RefreshActionGroup，保留右键菜单中的四项：

- 刷新所有缓存。
- 刷新 XML 文件缓存。
- 刷新 Java 文件缓存。
- 刷新 Java 方法调用缓存。

刷新步骤：

1. 禁止重复点击并显示进度。
2. 调用 MyBatisCacheManager.performFullCacheRefresh。
3. 等待缓存版本变化。
4. 重新构建关系快照。
5. 在 EDT 更新树。
6. 恢复仍存在节点的展开状态。
7. 异常时保留旧树并显示 Notification。

### 4.2 搜索

使用 IDEA 内置 SearchTextField，搜索按钮负责显示和关闭搜索框。

搜索范围：

- SQL ID。
- Java/XML 文件名。
- 完整路径。
- Java 元素类型。
- XML 标签名。
- databaseId。

规则：

- 大小写不敏感。
- 使用包含匹配实现模糊搜索。
- 输入采用防抖。
- Esc、清空按钮和关闭按钮都能关闭或清空搜索。
- 搜索只过滤快照，不触发扫描和数据库写入。
- 没有结果时显示空状态。

可在树控件上补充 TreeSpeedSearch，使键盘搜索行为符合 IDEA 习惯。

### 4.3 视图选项

第一版提供：

- 不分组。
- 按目录分组。
- 按模块分组。

目录分组使用项目根目录的相对父路径逐级生成节点。模块分组使用 ProjectFileIndex.getModuleForFile。没有模块的文件放入“未归属模块”。

分组设置保存在项目级 PersistentStateComponent，只保存 UI 状态，不写入缓存数据库。

### 4.4 缓存范围

提供两个选项：

- 全部缓存，默认。
- 仅关联关系。

全部缓存包含 element_java 和 element_xml 的全部有效记录，包括孤立 Java 或 XML。

仅关联关系只保留同时存在 Java 记录和 XML 记录的 SQL ID。XML 记录还必须按 databaseId 区分。

## 5. 页签与数据类型

使用 IntelliJ 的 Tab 组件创建两个页签：

- 当前。
- 所有。

所有页签顶部增加下拉框：

- 所有，默认。
- Java。
- XML。

页签、下拉框、缓存范围、分组和搜索状态由同一个面板状态管理，但每个页签应保存自己的展开路径。

## 6. 数据与树模型

### 6.1 查询快照

新增 CacheRelationQueryService，负责：

1. 从 MyBatisCache 获取不可变原始快照。
2. 构建 SQL ID、文件、Java 引用、XML 引用索引。
3. 根据页签、数据类型、搜索文本、缓存范围和分组生成树数据。
4. 返回 CacheRelationSnapshot。
5. 提供懒加载节点的子节点查询。

不允许 UI 层直接拼 SQL 或直接调用 DAO。

### 6.2 记录模型

Java 记录适配字段：

- filePath
- startOffset
- endOffset
- lineNumber
- elementType
- sqlId
- sourceStatus

XML 记录适配字段：

- filePath
- startOffset
- endOffset
- lineNumber
- tagName
- sqlId
- databaseId
- sourceStatus

lineNumber 在展示阶段通过 Document 或 PSI 计算，不写入缓存表。

sourceStatus：

- VALID。
- FILE_NOT_FOUND。
- OFFSET_INVALID。
- INDEX_NOT_READY。

### 6.3 节点类型

树节点至少包括：

- ROOT。
- MODULE_GROUP。
- DIRECTORY_GROUP。
- FILE。
- SQL_ID。
- JAVA_REFERENCE。
- XML_REFERENCE。
- DATABASE_VARIANT。
- EMPTY。
- ERROR。

每个节点必须使用稳定 NodeKey：

- 文件：文件类型 + 文件路径。
- SQL ID：展示侧别 + SQL ID。
- Java 引用：文件路径 + 起始偏移 + 结束偏移 + SQL ID。
- XML 引用：文件路径 + databaseId + 起始偏移 + 结束偏移 + SQL ID。

不能使用显示文本作为唯一标识。

## 7. 当前页签

当前页签通过 FileEditorManager.getSelectedTextEditor 获取当前编辑器文件。

处理步骤：

1. 获取当前 VirtualFile。
2. 判断文件类型是否为 Java 或 XML。
3. 用文件路径查询 SQL ID 集合。
4. 查询 SQL ID 对应的另一侧记录。
5. 只展示当前文件涉及的 SQL ID。
6. 当前文件不是 Java/XML 时显示空状态。
7. 当前文件没有 SQL ID 时显示空状态。
8. 全部缓存模式下保留当前文件的孤立 SQL ID。
9. 仅关联关系模式下隐藏孤立 SQL ID。
10. 编辑器切换、文件关闭或文档变化时防抖刷新当前页签。

当前 Java 文件的建议树：

- 当前 Java 文件。
  - SQL ID。
    - XML 文件。
      - databaseId。
        - XML 定位。

当前 XML 文件对称展示 Java 文件、Java 类/方法和引用行。

## 8. 所有页签

### 8.1 所有

建议树：

- 分组。
  - SQL ID。
    - Java 文件。
      - Java 引用行。
    - XML 文件。
      - databaseId。
        - XML 定位。

搜索 SQL ID 时，同时展示所有涉及的 Java 和 XML 文件。全部缓存模式保留孤立 SQL ID。

### 8.2 Java

建议树：

- 分组。
  - Java 文件。
    - SQL ID。
      - Java 引用行。
      - XML 文件。
        - databaseId。
          - XML 定位。

规则：

1. 同一个 Java 文件或类中多处引用同一 SQL ID，SQL ID 节点只保留一份。
2. SQL ID 下保留所有引用行号。
3. 同一 SQL ID 只有唯一 Java 引用时，可以省略 SQL ID 中间层，直接展示 XML 列表。
4. 一个 SQL ID 对应多个 XML 文件时全部展示。
5. 同一 XML 文件中相同 SQL ID 的不同 databaseId 必须拆分。
6. 没有 XML 对应项时保留 Java 孤立节点。

### 8.3 XML

建议树：

- 分组。
  - XML 文件。
    - SQL ID。
      - databaseId。
        - Java 文件。
          - Java 引用行。

规则：

1. 相同 XML 文件、SQL ID、databaseId 的重复记录按定位合并。
2. 相同 SQL ID 的多个 Java 文件全部展示。
3. Java 端只有唯一引用时可以直接进入 Java 文件节点。
4. 不同 databaseId 绝不能合并。
5. 没有 Java 对应项时保留 XML 孤立节点。

## 9. 跳转设计

新增 CacheNavigationService：

1. 通过 LocalFileSystem 按路径获取 VirtualFile。
2. 使用 FileEditorManager 打开文件。
3. 使用 TagLocator 按偏移量定位 PSI。
4. Java 引用节点跳转到具体引用行。
5. XML 引用节点跳转到具体标签。
6. 文件节点跳转到该文件第一条缓存记录。
7. 偏移量失效时重新解析文件，并按 SQL ID、元素类型或标签名做有限回退。
8. 找不到时仍打开文件，并提示缓存定位已经失效。
9. PSI 查询使用 Read Action，打开编辑器使用 EDT。

## 10. 刷新事件与并发

建议增加 MyBatisCacheChangedTopic，事件包含：

- cacheVersion。
- refreshRange。
- changedFilePaths。
- success。
- errorMessage。

Tool Window 订阅后：

- 当前文件受影响时刷新当前页签。
- 任意相关缓存变化时刷新所有页签。
- 新查询必须带递增 querySequence。
- 只有最新 querySequence 的结果可以更新树。
- 查询开始和结束比较 cacheVersion，版本变化则丢弃结果并重试。
- 项目关闭或插件卸载时取消监听、停止任务、释放模型。

## 11. 实施顺序

### 阶段一：只读查询模型

1. 使用 IDEA MCP 搜索并确认所有 MyBatisCache 查询入口。
2. 新增查询快照和关系索引。
3. 增加 databaseId 维度。
4. 增加孤立数据过滤。
5. 编写纯 Java 单元测试。

完成标准：不依赖 UI 可以得到所有、Java、XML、当前四类结果。

### 阶段二：Tool Window 基础能力

1. 增加 Tool Window Factory 和 plugin.xml 局部注册。
2. 设置项目图标。
3. 增加当前/所有页签。
4. 增加基础树模型。
5. 增加文件和记录跳转。
6. 增加加载、空、错误状态。

完成标准：打开侧边栏能看到缓存，并能跳转源文件。

### 阶段三：工具栏

1. 局部新增刷新入口并复用 RefreshActionGroup。
2. 增加搜索框、清空和关闭。
3. 增加全部缓存/仅关联关系。
4. 增加所有/Java/XML 下拉框。
5. 增加全部展开和全部收起。

完成标准：工具栏所有按钮和状态切换可用。

### 阶段四：分组与懒加载

1. 增加目录分组。
2. 增加模块分组。
3. 实现文件、SQL ID、关系节点懒加载。
4. 实现重复引用合并。
5. 实现 databaseId 变体。
6. 增加查询防抖和版本保护。

完成标准：中等规模项目下操作不阻塞 UI。

### 阶段五：联动验证

1. 验证文件修改、删除、重命名后的节点更新。
2. 验证缓存刷新后树自动更新。
3. 验证项目关闭和插件卸载资源释放。
4. 使用 IDEA MCP 编译项目。
5. 启动插件沙箱验证 Java/XML 双向跳转。

## 12. 测试和验收

必须覆盖：

- Java/XML 一对一关系。
- Java 同一 SQL ID 多处引用。
- 多个 Java 方法引用同一 SQL ID。
- 一个 SQL ID 对应多个 XML 文件。
- 一个 XML 文件同一 SQL ID 多个 databaseId。
- 只有 Java 或只有 XML 的孤立缓存。
- 相同文件名不同路径。
- 文件不存在和偏移量失效。
- 搜索 SQL ID、路径、文件名、databaseId。
- 全部缓存与仅关联关系的差异。
- 当前编辑器切换。
- 全部展开和全部收起。
- 刷新菜单与右键菜单一致。
- 所有/Java/XML 下拉框。
- Tool Window 关闭、项目关闭和插件卸载。

验收条件：

1. 默认能看到全部缓存。
2. 当前页签能跟随当前 Java/XML 文件。
3. 所有页签能按三种数据类型切换。
4. SQL ID 模糊搜索能找到所有涉及文件。
5. 重复引用合并后行号不丢失。
6. 不同 databaseId 不会错误合并。
7. 所有文件和定位记录可跳转。
8. IDEA MCP 编译成功。
9. 现有右键刷新功能行为不变。

## 13. 实施注意事项

- 先实现查询模型，再实现 UI。
- 每次只用 IDEA MCP 的局部补丁修改需要的文件。
- 不要为了 Tool Window 重新生成现有缓存管理器、解析器或 plugin.xml。
- 每完成一个阶段就使用 IDEA MCP 编译。
- 如果 IntelliJ API 在当前平台版本中有差异，以 IDEA MCP 的符号解析和编译错误为准调整。
- 具体类名可以按现有包结构微调，但职责边界不能混淆。
