# 缓存关系侧边栏实施计划

## 1. 实施范围

本计划只描述代码实施，最终以 IDEA MCP 编译通过作为完成条件。

实施目标：新增项目级 IntelliJ Tool Window，展示当前项目持有的 MyBatis Java/XML 缓存，并以 SQL ID 为中心展示关联关系。

必须遵守：

- 使用 IDEA MCP 搜索代码、分析符号和修改文件。
- 使用局部补丁，只修改必要内容。
- 不重新生成已有缓存管理器、解析器或 plugin.xml。
- 不改变已有右键刷新和 Java/XML 双向跳转行为。
- UI 不直接访问 DAO 或数据库。
- 不长期持有 PSI 对象。
- 每个实施阶段完成后使用 IDEA MCP 编译，出现编译错误时只修改必要文件。

## 2. 实施顺序

1. 缓存查询模型。
2. Tool Window 基础框架。
3. 当前页签。
4. 所有页签。
5. 源文件跳转。
6. 顶部工具栏。
7. 搜索和筛选。
8. 分组与树操作。
9. 缓存事件联动。
10. 生命周期和性能处理。

## 3. 阶段一：缓存查询模型

### 目标

把现有缓存转换成 UI 可以使用的不可变关系快照。

### 实施内容

新增项目级 CacheRelationQueryService，负责：

- 读取 MyBatisCache。
- 构建 SQL ID 到 Java 记录的索引。
- 构建 SQL ID 到 XML 记录的索引。
- 构建文件到 SQL ID 的反向索引。
- 构建文件类型、模块和目录信息。
- 按 SQL ID 计算 Java/XML 是否存在关联。
- 按 databaseId 拆分 XML 记录。
- 根据缓存范围过滤孤立数据。
- 根据搜索条件过滤结果。
- 根据页签和数据类型生成树节点数据。

新增只读模型：

- CacheRelationSnapshot。
- CacheFileSummary。
- SqlIdRelation。
- JavaCacheRecord。
- XmlCacheRecord。

JavaCacheRecord 保存文件路径、偏移量、元素类型、SQL ID 和展示状态。

XmlCacheRecord 保存文件路径、偏移量、标签名、SQL ID、databaseId 和展示状态。

展示行号在读取 Document 或 PSI 时计算，不写回缓存表。

## 4. 阶段二：Tool Window 基础框架

### 实施内容

新增：

- MyBatisCacheToolWindowFactory。
- MyBatisCacheToolWindowPanel。
- CacheTreeNode。
- CacheTreeNodeKey。
- CacheTreeNodeType。

局部修改 plugin.xml：

- 增加项目级 Tool Window。
- Tool Window 停靠在右侧。
- 注册 Factory。
- 使用 AllIcons.Nodes.Project 作为图标。

面板负责：

- 创建树控件。
- 创建页签容器。
- 创建工具栏容器。
- 管理当前项目上下文。
- 管理查询服务和树模型实例。

树节点类型至少包括：

- ROOT。
- MODULE_GROUP。
- DIRECTORY_GROUP。
- FILE。
- SQL_ID。
- JAVA_REFERENCE。
- XML_REFERENCE。
- DATABASE_VARIANT。
- EMPTY。
- ERROR。

NodeKey 必须使用文件路径、偏移量、SQL ID 和 databaseId 等稳定字段，不能只使用显示文本。

## 5. 阶段三：当前页签

### 实施内容

新增 CurrentCacheTab，处理当前编辑器上下文：

1. 通过 FileEditorManager 获取当前编辑器。
2. 获取当前 VirtualFile。
3. 判断当前文件是 Java 还是 XML。
4. 查询当前文件的 SQL ID。
5. 查询 SQL ID 对应的另一侧记录。
6. 生成当前关系树。
7. 编辑器切换时刷新当前页签。
8. 文档变化时防抖刷新当前页签。
9. 当前文件不是 Java/XML 时显示空节点。
10. 当前文件没有 SQL ID 时显示空节点。
11. 全部缓存模式保留孤立 SQL ID。
12. 仅关联关系模式隐藏孤立 SQL ID。

当前 Java 的树结构：

- 当前 Java 文件。
  - SQL ID。
    - XML 文件。
      - databaseId。
        - XML 定位。

当前 XML 使用对称结构：

- 当前 XML 文件。
  - SQL ID。
    - databaseId。
      - Java 文件。
        - Java 引用行。

## 6. 阶段四：所有页签

### 实施内容

新增 AllCacheTab，并增加数据类型选择：

- 所有。
- Java。
- XML。

所有视图：

- 分组。
  - SQL ID。
    - Java 文件。
      - Java 引用行。
    - XML 文件。
      - databaseId。
        - XML 定位。

Java 视图：

- 分组。
  - Java 文件。
    - SQL ID。
      - Java 引用行。
      - XML 文件。
        - databaseId。
          - XML 定位。

XML 视图：

- 分组。
  - XML 文件。
    - SQL ID。
      - databaseId。
        - Java 文件。
          - Java 引用行。

重复处理规则：

1. 同一 Java 文件或类中多处引用同一个 SQL ID 时，只显示一个 SQL ID 节点。
2. SQL ID 节点下保留所有引用行。
3. SQL ID 只有唯一引用时，可省略 SQL ID 中间节点。
4. 一个 SQL ID 对应多个 XML 文件时全部保留。
5. 一个 XML 文件中相同 SQL ID 的不同 databaseId 必须拆分。
6. 只有 Java 或只有 XML 的记录作为孤立节点保留或过滤。

## 7. 阶段五：源文件跳转

### 实施内容

新增 CacheNavigationService：

1. 根据文件路径查找 VirtualFile。
2. 使用 FileEditorManager 打开文件。
3. 使用 TagLocator 按偏移量定位目标 PSI。
4. Java 文件节点跳转到对应 Java 文件。
5. Java 引用节点跳转到具体引用行。
6. XML 文件节点跳转到对应 XML 文件。
7. XML 记录节点跳转到具体 XML 标签。
8. databaseId 节点跳转到对应 XML 标签。
9. 偏移量失效时按 SQL ID、元素类型或标签名进行有限回退。
10. 文件不存在或无法定位时返回可显示的失效状态。

## 8. 阶段六：顶部工具栏

### 实施内容

新增 MyBatisCacheToolbar，包含：

- 刷新按钮。
- 搜索按钮。
- 视图选项按钮。
- 全部缓存/仅关联关系按钮。
- 全部展开按钮。
- 全部收起按钮。

刷新按钮复用 RefreshActionGroup，不复制已有刷新逻辑。保留：

- 刷新所有缓存。
- 刷新 XML 文件缓存。
- 刷新 Java 文件缓存。
- 刷新 Java 方法调用缓存。

工具栏按钮使用 IntelliJ AnAction、ActionToolbar 和标准图标。

## 9. 阶段七：搜索和筛选

### 实施内容

新增 CacheSearchController：

- 使用 SearchTextField。
- 搜索按钮显示搜索框。
- 支持清空、关闭和 Esc。
- 输入变化采用防抖。
- 大小写不敏感。
- 使用包含匹配进行模糊搜索。

匹配字段：

- SQL ID。
- 文件名。
- 文件路径。
- Java 元素类型。
- XML 标签名。
- databaseId。

搜索只过滤当前快照，不触发缓存刷新，不写数据库。

## 10. 阶段八：分组和树操作

### 实施内容

新增视图状态和分组处理：

- 不分组。
- 按目录分组。
- 按模块分组。

目录分组使用项目根目录相对路径逐级生成。

模块分组使用 ProjectFileIndex 获取模块。无模块文件归入未归属模块。

新增：

- CacheToolWindowState。
- CacheTreeExpander。
- LazyCacheTreeNode。

实现：

- 文件节点懒加载 SQL ID。
- SQL ID 节点懒加载另一侧文件。
- 关系节点懒加载定位记录。
- 全部展开递归加载并展开。
- 全部收起递归收起。
- 刷新后恢复仍存在的展开节点。

视图状态保存在项目级 PersistentStateComponent，不写入缓存数据库。

## 11. 阶段九：缓存事件联动

### 实施内容

新增缓存变化消息：

- MyBatisCacheChangedTopic。
- MyBatisCacheChangedEvent。

事件字段：

- cacheVersion。
- refreshRange。
- changedFilePaths。
- success。
- errorMessage。

局部修改 MyBatisCacheManagerDefault：

- 刷新完成后发布缓存事件。
- 文件修改、删除和重命名后发布受影响路径。
- 保持已有刷新逻辑不变。

Tool Window 订阅事件：

- 当前文件受影响时刷新当前页签。
- 任意缓存变化时刷新所有页签。
- 只接收最新查询结果。
- 缓存版本变化时丢弃旧快照。

## 12. 阶段十：生命周期和性能

### 实施内容

新增 CacheTaskController，统一管理：

- 后台快照查询。
- 搜索防抖任务。
- 编辑器变化任务。
- 缓存变化任务。
- 懒加载任务。

约束：

- 后台线程执行关系整理。
- EDT 只更新树模型和组件。
- 使用不可变集合传递快照。
- 不在 UI 节点中保存 PSI。
- 项目关闭时取消任务和订阅。
- Tool Window 销毁时释放监听器。
- 插件卸载时清理 Message Bus、任务和项目引用。
- 数据量较大时使用懒加载和分段展开。

## 14. 实施原则

1. 先实现查询服务，再连接 UI。
2. 先实现完整关系，再增加懒加载优化。
3. 先支持不分组，再增加目录和模块分组。
4. 所有 UI 状态与缓存数据分离。
5. 所有跳转通过统一导航服务。
6. 所有刷新通过现有刷新命令。
7. 每次修改只提交必要的局部差异。
8. 最终必须通过 IDEA MCP 编译，除此之外不安排单元测试、沙箱验证或发布任务。
