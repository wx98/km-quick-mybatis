### 2.3 Cache 模块

`MyBatisCache` 是缓存领域接口，提供 Java/XML 元素的增删查、SQL ID 关联查询、文件摘要和范围清理。`MyBatisCacheDefault` 组合三个 DAO，负责把解析结果转换成数据库操作。

`MyBatisCacheFactory` 与 `MyBatisCacheManagerFactory` 是工厂门面，分别返回缓存和缓存管理器的推荐实现。

`MyBatisCacheRefreshRange` 定义四种清理范围：`JAVA`、`XML`、`JAVA_METHOD_CALL`、`ALL`。Java 方法调用记录使用 `element_type = 'methodCall'` 区分。

`MyBatisCacheManagerDefault` 的关键算法如下：

1. 构造时创建缓存实现并注册 VFS 监听、启动定时扫描。
2. VFS 监听过滤排除目录、非源码目录、非 Java/XML 文件和 dumb mode。
3. 内容修改/删除事件调用 `refreshInvalidatedCaches`。
4. 刷新时先取当前文件关联的 SQL ID，再找到同一 SQL ID 关联的全部文件，删除旧缓存并重新解析。
5. 定时扫描比较 `file_digest`，对修改、删除、新增文件分别执行清理和重建。
6. PSI 解析全部置于 `ReadAction`；索引未就绪时通过 `DumbService.runWhenSmart` 延迟。
7. `dispose()` 使用 `shutdownNow()` 停止调度器，断开消息总线连接，并清除项目 user data。

### 2.4 Parser 模块

`JavaParser`、`MyBatisXmlParser` 只定义解析契约；对应的 `*Default` 类提供当前实现；`*Factory` 负责创建实例。

`MyBatisXmlStructure` 是 XML 语义常量中心：

- 语句标签：`select`、`insert`、`update`、`delete`。
- 辅助标签：`sql`、`resultMap`、`parameterMap`、`cache`、`cache-ref`。
- 语句通用属性和 insert/select 等特有属性。
- Mapper DTD URL。

XML 解析结果按 `namespace`、statement ID、SQL fragment ID 和 resultMap ID 建立 Map。解析无效文件时抛出带有“不是有效的MyBatis XML文件”语义的异常。

Java 解析结果包含类、接口、接口方法、方法调用和静态字符串字段。`parseEverything` 比普通 `parse` 多收集方法调用，用于识别 SqlSession 访问。

### 2.5 Provider 模块

`LineMarkerProvider` 是共享抽象基类。`JavaLineMarkerProvider` 和 `XmlLineMarkerProvider` 均继承 IntelliJ `RelatedItemLineMarkerProvider`。

Java 提供器：

- 识别可映射 Java 元素。
- 查询 XML 元素信息。
- 使用 `TagLocator` 恢复 XML `XmlTag`。
- 生成带自定义图标和 renderer 的导航标记。

XML 提供器：

- 通过 `DomUtils.isMybatisFile` 过滤文件。
- 识别 mapper 根标签和四类 statement 标签。
- 使用 `namespace + "." + id` 形成完整 SQL ID。
- 查询 Java 元素信息并恢复 PSI 类或方法。
- 为方法调用目标生成包含行号和调用表达式的展示文本。

### 2.6 Service 模块

`JavaService` 管理项目级 Java PSI 辅助操作，包含 Java 文件枚举、SqlSession 方法识别、表达式解析和参数替换。

`XmlService` 管理项目级 XML 文件获取，遍历项目内容根和源码目录，筛选 MyBatis XML。

服务对象不直接承担缓存持久化，避免 PSI 遍历和数据库索引耦合。

### 2.7 Lifecycle 模块

`MyApplicationActivationListener` 在 IDEA 窗口激活时读取应用级类过滤器并记录调试日志。

`MyBatisStartupLoader` 是 `ProjectActivity`。它触发缓存管理器初始化并创建守护 Timer，每 5 秒执行缓存版本检查；项目销毁后取消 Timer。

`MyBatisCloseSaver` 实现 `ProjectCloseHandler`，关闭项目数据库服务并允许项目继续关闭。

`MyBatisUnloadListener` 的卸载详细流程：

```text
beforePluginUnload
  -> 校验 pluginDescriptor.pluginId
  -> 遍历 ProjectManager.openProjects
       -> getExistingInstance，避免卸载过程中创建新缓存管理器
       -> dispose scheduler/message bus
       -> getServiceIfCreated(DataBaseManager)，避免创建新数据源
       -> close active datasource
  -> 若不是 update
       -> 删除项目配置、通知配置、H2 数据库及辅助文件
       -> 删除 APP_CONFIG/options/KmQuickMybatis.xml
```

卸载删除操作只对明确拼接出的项目 `.idea` 文件和 IDEA options 文件执行，删除失败记录 warning，不影响其余项目处理。

### 2.8 Setting 模块

`MyPluginSettings` 是应用级 `PersistentStateComponent`，保存 `ClassFilter[]`。`MyPluginConfigurable` 实现 IDEA 设置页面，比较过滤器集合并执行 apply/reset。

`MyPluginSettingsFrom` 负责表单初始化和获取当前活动项目。`MybatisClassFilterEditor` 在 IDEA 类过滤器控件基础上增加类选择器，并限制添加动作在默认项目中不可用。

`MyBatisSetting` 是项目级持久化组件，保存：

- `classNamingRule`，默认 `${className}`。
- `methodNamingRule`，默认 `${className}.${methodName}`。
- `fieldNamingRule`，默认 `${className}.${fieldName}`。
- SqlSession 方法正则模式。

## 3. 数据库详细设计

### 3.1 `element_java`

字段：`sql_id`、`file_path`、`element_type`、`start_offset`、`end_offset`。文件路径和元素类型有普通索引，SQL ID、路径、元素类型和起始偏移量形成唯一约束。

### 3.2 `element_xml`

字段：`sql_id`、`file_path`、`tag_name`、`database_id`、`start_offset`、`end_offset`。文件路径、标签名和数据库 ID 有普通索引；SQL ID、路径、标签名、数据库 ID 和起始偏移量形成唯一约束。

### 3.3 `file_digest`

字段：`file_path`、`digest`。文件路径唯一，更新摘要即可表示最新扫描基线。

## 4. 线程与读写边界

- PSI 查询和文本范围读取在 `ReadAction` 中执行。
- 文件摘要并行计算使用专用线程池和超时保护。
- 缓存定时任务使用单线程 `ScheduledExecutorService`，通过 `scanLock` 防止扫描重入。
- 文件修改事件不在 UI 线程执行完整解析。
- dumb mode 下不强行查询索引，改为 smart mode 回调。
- 数据库连接由 DAO 使用 try-with-resources 获取和释放；连接池由 `DataBaseManager.close()` 统一关闭。

## 5. 错误处理与降级

- 文件消失：清除缓存并跳过重新解析。
- PSI 文件为空：结束当前文件处理。
- 索引未就绪：延迟执行或记录 warning。
- XML 增强校验异常：`DomUtils` 回退基础 Mapper 判断。
- 解析未知异常：记录日志，避免影响 IDEA 主进程。
- 卸载文件删除失败：记录 warning，继续处理其它目标。

## 6. 当前实现中的注意事项

1. `MyBatisCacheManager` 接口中的静态 `getInstance` 当前返回 `null`，实际调用应使用 `MyBatisCacheManagerFactory` 或 `MyBatisCacheManagerDefault`。
2. `MyBatisStartupLoader` 自己创建的 Timer 与缓存管理器的 scheduler 是两套任务资源；当前 Timer 通过项目销毁停止，卸载设计主要释放缓存管理器资源。后续可考虑把版本检查 Timer 纳入统一 Disposable 生命周期。
3. `MyBatisXmlParser.MyBatisParseResult` 提供 fragments、resultMaps 等扩展结果，但当前测试明确允许部分实现返回空集合，导航主链路依赖 statements 和 namespace。
4. `TagLocator` 的 Java 恢复逻辑以起始偏移处 PSI 元素为入口，XML 恢复逻辑包含精确匹配和最内层范围兜底；复杂 Java AST 场景仍应补充更精确的类型校验。
5. 应用配置和项目配置采用不同持久化范围，卸载清理必须同时处理两类文件，不能只清除项目 `.idea`。

## 7. 验证建议

建议验证以下场景：

- 首次打开含 Mapper XML 的项目后，Java/XML 两侧都能出现行标记。
- 修改 statement `id`、namespace 或 Java 方法名后，VFS 事件和定时扫描均能恢复关联。
- 删除 XML/Java 文件后，对应缓存记录被清除。
- IDEA 索引未完成时编辑文件，不出现异常弹窗，索引完成后能补建缓存。
- 手动执行四种刷新动作，通知内容和缓存范围匹配。
- 关闭项目后 H2 数据源被关闭。
- 卸载插件时清理运行资源和插件持久化文件，更新插件时保留配置和缓存。
