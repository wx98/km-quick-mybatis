# Km-Quick-Mybatis 设计文档

## 1. 设计目标

插件的总体设计围绕“低侵入地把 Java 与 MyBatis XML 关联起来”展开：使用 IntelliJ 原生 PSI 表示代码，使用本地 H2 保存跨文件索引，通过行标记扩展点提供导航，并在项目和插件生命周期节点释放资源。

设计优先级如下：

1. 导航结果正确且响应快。
2. 源文件变化后缓存最终一致。
3. 不影响 IDEA 编辑器和索引过程。
4. 项目之间互不污染。
5. 卸载插件后不遗留插件独有资源。

## 2. 总体架构

```text
IntelliJ IDEA 扩展点
        |
        +-- Actions ----------------------+ 
        |                                 |
        +-- LineMarker Providers           v
        |                         MyBatisCacheManager
        +-- Lifecycle --------------------+
                                          |
                                 MyBatisCacheDefault
                                          |
                            Parser / TagLocator / DAO
                                          |
                                  H2 + HikariCP
```

架构分为六层：

| 层次 | 职责 | 代表类 |
| --- | --- | --- |
| IDEA 集成层 | 注册动作、服务、扩展点和生命周期 | `plugin.xml` |
| 交互层 | 提供菜单、快捷键、边栏导航 | `actions`、`provider` |
| 领域解析层 | 识别 MyBatis XML、Java 类/方法/调用 | `parser`、`services` |
| 缓存编排层 | 组织扫描、增量刷新、关系查询和版本 | `MyBatisCacheManagerDefault` |
| 持久化层 | 访问三张缓存表并管理连接池 | `DataBaseManager`、`cache.db` |
| 基础工具层 | 文件扫描、摘要、定位、通知、配置和图标 | `util`、`setting` |

## 3. IntelliJ 扩展点设计

`plugin.xml` 声明：

- Java、平台和 XML 模块依赖。
- 应用激活监听器和动态插件卸载监听器。
- Tools 菜单缓存刷新动作。
- 编辑器和项目视图右键根菜单。
- Java/XML 行标记提供器。
- Java、XML、通知、数据库、缓存管理器和配置项目服务。
- 项目启动活动和项目关闭处理器。
- 通知组、应用级配置和应用配置页面。

扩展点只负责把 IDEA 生命周期和用户操作接入领域服务，实际解析和缓存逻辑不放在 XML 注册层中。

## 4. 导航设计

### 4.1 关联主键

Java 和 XML 通过 SQL ID 关联：

```text
Mapper namespace = com.example.UserMapper
statement id     = selectById
完整 SQL ID       = com.example.UserMapper.selectById
```

Java 元素和 XML 元素除了 SQL ID，还保存绝对文件路径和 PSI 文本偏移量。这样导航查询只需要在索引中查 SQL ID，然后重新打开目标文件并恢复 PSI 元素。

### 4.2 Java 侧流程

1. `JavaLineMarkerProvider` 接收 Java PSI 元素。
2. 判断当前元素是否为 Mapper 类、方法、字段或目标 SqlSession 调用。
3. 从缓存查询 SQL ID 对应的 XML 元素。
4. 调用 `TagLocator.findXmlTagByInfo` 通过文件和偏移量定位 XML 标签。
5. 使用 `NavigationGutterIconBuilder` 创建边栏导航标记。

### 4.3 XML 侧流程

1. `XmlLineMarkerProvider` 判断当前 token 是否位于有效 Mapper XML。
2. 对 `mapper` 标签读取 `namespace`，查询 Java 类元素。
3. 对 SQL statement 读取 `id`，从根 `mapper` 读取 `namespace` 并拼接 SQL ID。
4. 查询 Java 元素缓存。
5. 调用 `TagLocator.findJavaTagByInfo` 定位目标 PSI 元素。
6. 创建 XML 到 Java 的导航标记和展示文本。

## 5. 解析设计

### 5.1 XML 解析

`MyBatisXmlParser` 抽象了 XML 解析器，`MyBatisXmlParserDefault` 提供当前实现，工厂类负责创建默认或推荐实例。

解析结果按命名空间、statement、SQL 片段和 resultMap 组织。`MyBatisXmlStructure` 集中定义 MyBatis 标签、通用属性、语句专属属性、DTD 地址和判断方法。

有效性检查至少包括：

- 文件必须是 `XmlFile`。
- 根标签必须为 `mapper`。
- `namespace` 必须存在且非空。
- 解析器增强校验失败时由 `DomUtils` 回退到基础判断，防止单次校验异常影响编辑器功能。

### 5.2 Java 解析

`JavaParser` 抽象 Java 解析结果，`JavaParserDefault` 使用 PSI 读取：

- 类和接口。
- 接口方法。
- 静态字符串字段。
- 配置类中的目标 SqlSession 方法调用。

`JavaService` 负责 Java 领域辅助逻辑，包括表达式文本解析、方法调用识别、字符串参数替换和 Java 文件枚举。

## 6. 缓存设计

### 6.1 运行时对象关系

```text
Project
  └── MyBatisCacheManagerDefault
        ├── MyBatisCacheDefault
        │     ├── JavaElementDao
        │     ├── XmlElementDao
        │     └── FileDigestDao
        ├── ScheduledExecutorService
        └── MessageBusConnection
```

缓存管理器按项目单例存放在 `Project` user data 中。其内部缓存对象负责领域数据，管理器负责生命周期、扫描和跨文件刷新。

### 6.2 持久化表

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `element_java` | Java 元素到 SQL ID 的索引 | `sql_id`、`file_path`、`element_type`、偏移量 |
| `element_xml` | XML 元素到 SQL ID 的索引 | `sql_id`、`file_path`、`tag_name`、`database_id`、偏移量 |
| `file_digest` | 文件变化检测 | `file_path`、`digest` |

表使用文件路径索引和唯一索引支持按文件清理、按 SQL ID 查询和增量写入。DAO 使用 Apache Commons DbUtils 执行参数化 SQL，批量写入采用事务。

### 6.3 一致性策略

文件发生变化时先移除受影响 SQL ID 的旧关系，再重新解析并写入新关系。文件摘要用于补偿未捕获的外部变化。缓存版本号通过 `AtomicLong` 递增，启动检查器每 5 秒检查一次并根据版本决定是否通知。

## 7. 生命周期设计

### 7.1 项目启动

`MyBatisStartupLoader` 获取推荐缓存管理器，读取当前缓存版本，并启动守护 `Timer`，每 5 秒执行一次缓存失效通知检查。缓存管理器自身同时注册 VFS 监听和 5 分钟摘要扫描。

### 7.2 项目关闭

`MyBatisCloseSaver` 在项目关闭前关闭 `DataBaseManager` 的数据源，释放 HikariCP 和 H2 相关连接。

### 7.3 插件卸载

`MyBatisUnloadListener` 只处理匹配插件 ID 的事件。资源释放和文件清理分开：资源释放无论更新还是卸载都执行；插件专属持久化文件仅在 `isUpdate == false` 时删除。

## 8. 配置与持久化设计

| 配置 | 范围 | 文件 |
| --- | --- | --- |
| SqlSession 类过滤器 | 应用级 | `$APP_CONFIG$/options/KmQuickMybatis.xml` |
| 命名规则、方法模式 | 项目级 | 项目 `.idea/quick-mybatis-settings.xml` |
| 通知“不再提示”状态 | 项目级服务 | 项目 `.idea/km-quick-mybatis-notification.xml` |
| 解析索引 | 项目级缓存 | 项目 `.idea/km_mybatis_cache` H2 文件 |

## 9. 构建与测试设计

项目使用 Gradle Kotlin DSL、JDK 17 和 IntelliJ Platform Gradle Plugin；平台版本和插件版本由 `gradle.properties` 管理。测试基于 `BasePlatformTestCase`，当前重点覆盖：

- 有效/无效 MyBatis XML 识别。
- XML 解析结果和 statement 查询。
- 解析器工厂行为。
- XML 元素偏移量创建和反向定位。
